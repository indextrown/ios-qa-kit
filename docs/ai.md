# AI로 QA하기 (스킬 · MCP)

스킬로 시나리오를 만들게 하거나, MCP로 AI가 앱을 직접 눌러 보며 QA하게 합니다.

[← README](../README.md)

## 스킬로 시나리오 만들기

`qakit install-skill`이 Claude Code(`/qa-kit`)와 Codex(`$qa-kit`) 스킬을 설치합니다. 작업공간 폴더에서 AI를 열고 요청합니다.

```text
/qa-kit 로그인 화면에서 테스트 계정으로 로그인하면 홈 화면이 뜨는지 확인하는 테스트 만들어줘
```

AI는 `qakit do`로 화면을 탐색하고, 통과한 단계를 시나리오로 옮기고, `qakit run`이 통과할 때까지 고칩니다. 과정: [테스트가 만들어지는 과정](how-it-works.md#테스트가-만들어지는-과정) · 스킬 규칙: [SKILL.md](../skills/qa-kit/SKILL.md)

## AI가 직접 QA하기 (`qakit mcp`)

시나리오를 쓰기 전에 "이 화면 QA해 줘"처럼 **AI(Claude Code·Codex)가 앱을 직접 눌러 보며** 확인하게 합니다. qakit이 MCP 서버로 도구를 주고, AI는 사용자가 이미 로그인한 Claude Code·Codex 그대로 씁니다 (qakit은 토큰을 다루지 않음).

```bash
cd ~/path/to/MyApp-qa/QA
qakit mcp install --claude      # 이 폴더의 .mcp.json에 등록 → 여기서 claude를 열면 qakit 도구 사용 여부를 물음
qakit mcp install --codex       # codex mcp add (codex가 없으면 ~/.codex/config.toml에 넣을 내용 출력)
```

```text
qakit 도구로 검색 화면 QA해 줘. 빈 검색어, 아주 긴 검색어, 뒤로 가기까지 확인하고 문제는 보고해 줘.
```

| 도구 | 하는 일 |
|---|---|
| `get_testing_guide` | 확인할 항목, 여기서 못 하는 것, 거짓 버그 피하기, 보고 형식 (AI가 먼저 읽음) |
| `launch` · `screen` · `screenshot` | 앱 새로 켜기, 화면 구조(텍스트), 사진 (색·배치·지도 볼 때만 — 폭은 기기에 맞춤: 태블릿 1024, 폰 600, `width`로 바꿈) |
| `tap` · `type_text` · `swipe` · `wait_for` · `expect` · `step` | 시나리오 단계 그대로 (ID·라벨, 좌표 없음). `tap`에 `expect`를 주면 누른 효과까지 확인. `step`의 `steps`로 여러 줄을 한 번에 (실패하면 거기서 멈춤). 탭·단계 결과에는 **조작 뒤 화면이 붙어 와서** 다시 읽는 왕복이 줄어듭니다 (`QAKIT_AI_AUTOSCREEN=0`이면 끔) |
| `logs` | 앱 로그·크래시 (안드로이드 — `qakit android logs`와 같음, 비밀값 가림) |
| `recorded_steps` · `save_scenario` | 통과한 단계 → `scenarios/`에 저장, **앱을 새로 켜고 재생해서 통과해야** 남음 (실패하면 `.qakit/drafts/`) |
| `list_scenarios` · `run_scenario` · `list_common_steps` · `read_scenario` · `find_ids` | 있는 시나리오·공통 단계 보기·읽기(스타일 맞추기)·실행 (실패하면 "대신 이 대상?" 제안까지) |
| `report_issue` | 재현한 문제만 (`reproduced: true`), 사진과 **보고 직전 최대 30초 영상**(시뮬레이터)을 함께 `results/ai/<시각>/issues.md` |

- **같은 대상이 여럿**(예: 패널의 「close」와 카드의 「close」)이면 첫째를 누르지 않고 후보(`index`·#ID·어디 안에 있는지)를 돌려줘 AI가 고르게 합니다. 직접 터치에서는 누를 자리를 **다른 버튼이 덮고 있으면** 무엇이 덮었는지 알려 주고 누르지 않습니다.
- AI는 처음부터 **작업공간 사정**을 압니다: 기기·빌드·앱, 공통 단계(`use:` 이름과 설명), 시나리오 목록, 비밀값 키 이름(값은 넣지 않음). 맞는 공통 단계가 있으면 하나씩 누르지 않고 그것부터 씁니다.
- AI가 누르는 것은 모두 ID·라벨 단계라, 확인한 경로가 그대로 시나리오가 되고 이후엔 AI 없이 돕니다.
- **지켜보기**: `qakit ui` 라이브 세션을 열어 두면 오른쪽 위 **AI 활동**에 AI가 한 일(시각·동작·대상·이유·결과·걸린 시간)과 지금 하는 일, 보고한 문제(사진)가 쌓이고, 화면에서는 커서가 AI가 누르는 자리로 움직입니다. AI가 조작하는 동안 손 조작은 잠기고(입력이 섞이지 않게) 요소 상자는 숨깁니다. 기록은 `results/ai/<시각>/log.jsonl`.
- 비밀번호는 `{secret:키}`로만 칩니다. 도구 결과의 비밀값은 가립니다.
- `.mcp.json`에는 이 Mac의 경로가 들어 있으니 git에 올리지 않는 편이 좋습니다.

**AI로 시나리오 만들기**: AI QA 메뉴의 **시나리오 만들기** 모드(또는 시나리오 메뉴의 **AI로 만들기**, 커버리지의 **AI로 시나리오**)에서 확인할 흐름을 말로 적으면(예: "홈 → 검색 → 첫 결과 상세가 열리는지"), AI가 기존 시나리오·공통 단계를 읽어 스타일을 맞추고, 앱을 눌러 보며 경로를 찾아 화면 전환마다 확인(`expect`)을 넣고, 저장 → 새로 켠 앱에서 재생해 통과해야 남깁니다. 이름·태그·시작 공통 단계를 정할 수 있고, 삭제·결제처럼 되돌릴 수 없는 일은 하지 않습니다. 끝나면 저장된 시나리오로 바로 편집·실행. 시나리오를 만들 때 AI는 **앱 소스도 읽습니다**(읽기 전용 — Read·Grep·Glob만, 셸·수정 없음): 화면 코드에서 흐름·조건·ID를 확인하되, 근거는 실제 화면입니다.

**AI QA 결과 → 시나리오**: AI QA가 끝난 보고서나 세션 상세의 **이 결과로 시나리오 만들기**를 누르면, 그 세션의 목표·보고서·통과 단계·문제를 바탕으로 AI가 화면과 소스를 보며 확인된 흐름마다 시나리오를 만들어 재생 통과하면 저장합니다. (AI 없이 통과 단계를 그대로 옮기려면 세션 상세의 "시나리오로 저장")

**UI에서 (`qakit ui` → AI)**: 왼쪽은 기기 화면(AI가 누르는 자리로 커서가 움직임), 오른쪽은 **대화** 하나입니다. 입력칸 위에서 모드를 고릅니다.

| 모드 | 하는 일 |
|---|---|
| 대화 | 짧게 시키고 바로 답을 받습니다 ("설정 화면 열고 항목 알려줘"). 지금 화면에서 이어서 하고, 앞 대화를 기억합니다 (Claude Code 세션을 `--resume`으로 이어 감) |
| 맡기기 | 목표와 시간(3~30분)을 주면 AI가 혼자 QA하고 보고서를 대화에 붙입니다. 다음 말 때 AI가 그 보고서를 압니다. "확인한 경로를 시나리오로 저장"을 켜면 경로도 남깁니다 |
| 시나리오로 | 지금까지 대화에서 확인한 흐름(대화 기록 + 기록된 통과 단계)을 시나리오로 저장합니다 — 새로 켠 앱에서 재생해 통과해야 저장. 앱 소스도 읽게 할 수 있습니다 (읽기 전용) |

- 머리말에서 **모델**(계정 기본·Opus·Sonnet·Haiku)과 **추론 정도**(기본·낮음~최대, `claude --effort`)를 고릅니다. 대화 중에 바꾸면 다음 말부터.
- AI가 하는 중에도 말을 보낼 수 있습니다: **대기열에**(Enter)는 지금 차례가 끝나면 같은 대화로 이어서 보내고(최대 5개), **끼어들기**는 지금 일을 멈추고 그 말을 바로 보냅니다. **멈춤**은 기다리던 말도 버립니다.
- `qakit ui --build release`로 열면 AI도 같은 release 앱을 조작합니다. `--build` 없이 열면(맥 앱 포함) 그 작업공간에서 마지막으로 연 빌드로 엽니다.
- **멈춤**으로 끊고, **새 대화**로 처음부터. 지난 대화·작업은 같은 화면 아래 목록에서 다시 엽니다.
- AI는 qakit 도구만 씁니다 (셸·파일 수정 막음). 되돌릴 수 없는 일은 분명히 시킬 때만 합니다. AI가 조작하는 동안 손 조작·시나리오 실행은 막고, 라이브 세션에는 AI 활동만 보입니다.
- 결과는 `results/ai/<시각>/` (`chat.md` 대화 기록·`agent.jsonl`·`log.jsonl`·`issues.md`). 지금은 Claude Code만 (Codex는 시험하지 못함). iOS·안드로이드 모두.

**직접 터치 (tapflow 방식)**: AI QA(문제 찾기) 모드는 기본으로 **직접 터치**를 씁니다 — XCUITest 탭 대신 좌표로 바로 눌러 빠르고 — 상주 실행기가 떠 있으면 XCTest 이벤트 합성(약 0.35초, 시뮬레이터 상태와 상관없이 늘 먹힘), 없으면 시뮬레이터 HID 주입(`Tools/simtouch`, 약 0.1초, 부팅에 따라 무시될 수 있음) — **길게 누르기(`long_press`)·끌기(`drag`)·좌표 누르기(`tap_point`)** 도구가 더 생깁니다. 누를 자리는 화면 구조에서 대상(ID·라벨)을 찾아 정하고, 통과 단계는 ID 단계로 남아 시나리오로 옮길 수 있습니다 — 길게 누르기·끌기도 `long-press`·`drag` 단계로 남고(직접 터치가 아니면 XCUITest로 같은 단계를 실행), 좌표 누르기만 남지 않습니다. 화면 읽기·`expect` 확인은 떠 있는 실행기에 바로 요청해 빠릅니다(화면 읽기 약 0.4~0.7초, 확인 약 0.4초 — 실행기가 없거나 옛 코드면 `qakit do`로 띄움). 화면에 없는 대상은 XCUITest 탭으로 넘기고, 누른 뒤 화면이 1초 넘게 그대로면 "무시됐을 수 있음"을 AI에게 알립니다. 끄려면 AI QA 화면의 **직접 터치** 체크를 끕니다. 시나리오 만들기·시나리오 실행·터미널에서 연결한 MCP는 그대로 XCUITest입니다 (터미널에서도 쓰려면 MCP 환경 변수 `QAKIT_TOUCH=direct`). 라이브 세션에서도 도구 막대의 **직접 터치 (실험)**(번개 아이콘)를 켜면 손으로 같은 방식을 씁니다 — 클릭은 탭, 0.5초 넘게 꾹 누르면 길게 누르기, 끌면 끌기. 요소 위를 탭하거나 길게 누르면 그 단계(`tap`·`long-press`)가 기록됩니다 (화면 구조를 다시 읽기 전이면 기록하지 않음). 커서는 실제로 누른 자리에 나타나고, 끌기는 시작에서 끝으로 움직입니다.

**결과 모아 보기**: AI QA 메뉴 아래 **지난 AI QA**와 **실행 기록**에 AI 세션이 쌓입니다 (터미널의 AI가 `qakit mcp`로 한 것도). 세션을 누르면 보고서, 문제(재현 단계·기대·실제·사진), AI가 한 말·도구 기록(이유·실패 원인), **AI가 통과한 단계**가 나오고, 그 단계로 바로 **시나리오 초안 → 재생 → 저장**할 수 있습니다 (실패한 조작은 빠짐).
